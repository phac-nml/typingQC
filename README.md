# TypingQC Pipeline

This pipeline evaluates the outputs generated by `mikrokondo` for its built-in typing tools, ECTyper and SISTR. It assesses sequencing, assembly, and typing quality metrics to determine whether each sample receives an overall **PASS**, **FAIL**, or **WARNING** status, and it compiles the specific reasons for any warnings or failures.

For samples that meet all required quality thresholds for sequencing, assembly, and typing, the pipeline generates enhanced metadata, including validated _serotypes_ (SISTR and ECTyper), _toxin_ profiles (ECTyper), and _STX subtypes_ (ECTyper).

This pipeline can be used to assess sequencing quality for samples from any bacterial species.
Typing quality assessment is currently supported for Salmonella and Escherichia species only.

# Input

The input to the pipeline is a standard sample sheet (passed as `--input samplesheet.csv`) that looks like:

| SAMPLE  | MIKROKONDO_DATA             | PREDICTED_IDENTIFICATION_NAME | QC_STATUS_OVERALL | PREDICTED_PRIMARY_TYPE_NAME |
| ------- | --------------------------- | ----------------------------- | ----------------- | --------------------------- |
| SampleA | sample1.flat_sample.json.gz | Species                       | PASS/FAIL         | Serotype                    |

The structure of this file is defined in [assets/schema_input.json](assets/schema_input.json). Validation of the sample sheet is performed by [nf-validation](https://nextflow-io.github.io/nf-validation/).

## IRIDA-Next Optional Input Configuration

`typingQC` accepts the [IRIDA-Next](https://github.com/phac-nml/irida-next) format for samplesheets which can contain an additional column: `sample_name`

`sample_name`: An **optional** column, that overrides `sample` for outputs (filenames and sample names) and reference assembly identification.

`sample_name`, allows more flexibility in naming output files or sample identification. Unlike `sample`, `sample_name` is not required to contain unique values. `Nextflow` requires unique sample names, and therefore in the instance of repeat `sample_names`, `sample` will be suffixed to any `sample_name`. Non-alphanumeric characters (excluding `_`,`-`,`.`) will be replaced with `"_"`.

The sample sheet, when including the optional `sample_name` column, should look like:

| SAMPLE  | SAMPLE_NAME | MIKROKONDO_DATA             | PREDICTED_IDENTIFICATION_NAME | QC_STATUS_OVERALL | PREDICTED_PRIMARY_TYPE_NAME |
| ------- | ----------- | --------------------------- | ----------------------------- | ----------------- | --------------------------- |
| SampleA | A1          | sample1.flat_sample.json.gz | Species                       | PASS/FAIL         | Serotype                    |

An [example samplesheet](../assets/samplesheet.csv) has been provided with the pipeline, which includes the `sample_name` column.

# Parameters

The main parameters are `--input` as defined above and `--output` for specifying the output results directory. You may wish to provide `-profile singularity` to specify the use of singularity containers and `-r [branch]` to specify which GitHub branch you would like to run.

Other parameters (defaults from nf-core) are defined in [nextflow_schema.json](nextflow_schema.json).

# Running

To run the pipeline, please do:

```bash
nextflow run phac-nml/typingQC -profile singularity -r main -latest --input assets/samplesheet.csv --outdir results
```

Where the `samplesheet.csv` is structured as specified in the [Input](#input) section.
For more information see [usage doc](docs/usage.md)

# Output

A JSON file for loading metadata into IRIDA Next is output by this pipeline. The format of this JSON file is specified in our [Pipeline Standards for the IRIDA Next JSON](https://github.com/phac-nml/pipeline-standards#32-irida-next-json). This JSON file is written directly within the `--outdir` provided to the pipeline with the name `iridanext.output.json.gz` (ex: `[outdir]/iridanext.output.json.gz`).

# Pipeline Logic and Modules

## Module: SEQUENCEQC

### Purpose

Evaluates sequencing and assembly quality metrics generate by **mikrokondo** and summarizes sequencing-related issues that may impact genome typing confidence. Based on PulseNet Canada Guidelines for assessing the quality of sequence data (DED-C-350A).

This module reports **PASS**, **WARNING**, or **FAIL** outcomes and captures detailed QC messages for reporting and IRIDA Next ingestion.

### Decision Matrix

Sequencing QC evaluation follows a prioritized decision model:

| Condition                                 | Outcome                                            |
| ----------------------------------------- | -------------------------------------------------- |
| **CheckM2 contamination failure**         | `FAIL` – re-isolation and resequencing recommended |
| Failure of **absolute QC metrics**        | `FAIL` – resequencing recommended                  |
| Failure of **warning-level metrics only** | `WARNING` – review required                        |
| No QC failures detected                   | PASS or pass-through QC message                    |

#### Absolute QC Failure Metrics (FAIL)

Failure of any of the following metrics results in an immediate sequencing **FAIL**:

- `raw_average_quality`: greater or equal to 30
- `average_coverage`: greater or equal to 40

These indicate that the sequencing data does not meet minimum requirements for sequence quality. Typing results may or may not be affected.

#### Warning-Level Metrics (WARNING)

Failure of these metrics _in the absence of absolute failures_ results in a sequencing **WARNING**:

- `n50_value`
  - _Salmonella_ : ~90,000
  - _Escherichia_ : ~50,000
  - _Listeria_ : ~50,000
  - _Shigella_ : ~18,000
  - _Campylobacter_ : ~100,000
  - _Vibrio_ : ~100,000
- `nr_contigs`
  - _Salmonella_ : ~200
  - _Escherichia_ : ~500
  - _Listeria_ : ~200
  - _Shigella_ : ~500
  - _Campylobacter_ : ~150
  - _Vibrio_ : ~150
- `length`
  - _Salmonella_ : ~4,400,000 - 6,000,000
  - _Escherichia_ : ~4,500,000 - 6,000,000
  - _Listeria_ : ~2,700,000 - 3,200,000
  - _Shigella_ : ~4,300,000 - 5,000,000
  - _Campylobacter_ : ~1,400,000 - 2,000,000
  - _Vibrio_ : ~3,800,000 - 4,300,000
- `wgMLST loci count`
  - _Salmonella_ : ~3800
  - _Escherichia_ : ~3800
  - _Listeria_ : ~2500
  - _Shigella_ : ~3300
  - _Campylobacter_ : n/a
  - _Vibrio_ : n/a

Warnings indicate potential quality concerns that may still allow downstream typing, depending on context.

#### Contamination Check

- `checkm2_contamination` failures result in a sequencing **FAIL** with a recommendation for re-isolation and resequencing.

### SEQUENCEQC Notes

- Sequencing QC failures do **not** block typing QC for supported species.
- This module reports sequencing issues only; typing validation occurs downstream.

## Module: SISTRQC

### Purpose

Evaluates **Salmonella serotype predictions** generated by **SISTR** via mikrokondo and determines whether the predicted serovar is **valid, reportable, or failed**.
This module assigns a **typingQC_message** and captures relevant QC warnings or errors for reporting and IRIDA Next ingestion.

### Decision Matrix

SISTR QC status and serovar predictions are evaluated together to determine the outcome.

| Condition                                               | typingQC_message                                                                           |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| SISTR PASS or WARNING **and** serovar is reportable     | `[SISTR_PASS]`                                                                             |
| SISTR PASS or WARNING **but** no serovar predicted      | `[SISTR_FAIL] No serovar found in SISTR results.`                                          |
| SISTR PASS or WARNING **but** serovar is not reportable | `[TYPE_FAIL] Serovar '<serovar>' is NOT REPORTABLE. Perform TRADITIONAL SEROTYPING.`       |
| SISTR WARNING with H1 antigen failure                   | `[SISTR_FAIL] Serotyping unsuccessful. RESEQUENCING or TRADITIONAL SEROTYPING is advised.` |
| SISTR FAIL                                              | `[SISTR_FAIL] Serotyping unsuccessful. RESEQUENCING or TRADITIONAL SEROTYPING is advised.` |
| No SISTR data present                                   | `[FAIL] Re-run mikrokondo to generate SISTR data.`                                         |

### SISTRQC Notes

- Serovar validation is based on a curated list of [reportable Salmonella serovars](https://github.com/phac-nml/typingQC/blob/main/assets/reportable_serovars_241213.csv).
- H1 antigen-related warnings are treated as **serotyping failures** due to reduced prediction reliability.
- Final serotype validation is performed downstream in the `SEROTYPE` module.

## Module: ECTYPERQC

### Purpose

Evaluates **Escherichia serotype and virulence predictions** generated by **ECTyper** via mikrokondo.
This module validates **O/H serotypes**, **toxin genes**, and **STX subtypes**, and assigns a standardized **typingQC_message** for reporting and IRIDA Next ingestion.

### Decision Matrix

### Serotype

ECTyper serotyping QC status determines the primary typing outcome.

| ECTyper QC Status               | typingQC_message                                                                          |
| ------------------------------- | ----------------------------------------------------------------------------------------- |
| PASS (REPORTABLE)               | `[ECTYPER_PASS]`                                                                          |
| FAIL (-:- TYPING)               | `[ECTYPER_FAIL] RESEQUENCING or TRADITIONAL SEROTYPING is advised.`                       |
| WARNING (-:H TYPING)            | `[ECTYPER_FAIL] RESEQUENCING or TRADITIONAL SEROTYPING is advised.`                       |
| WARNING (O:- TYPING)            | `[ECTYPER_FAIL] RESEQUENCING or TRADITIONAL SEROTYPING is advised.`                       |
| WARNING (O NON-REPORT)          | `[ECTYPER_FAIL] THRESHOLD adjustment, RESEQUENCING or TRADITIONAL SEROTYPING is advised.` |
| WARNING (H NON-REPORT)          | `[ECTYPER_FAIL] THRESHOLD adjustment, RESEQUENCING or TRADITIONAL SEROTYPING is advised.` |
| WARNING (O AND H NON-REPORT)    | `[ECTYPER_FAIL] THRESHOLD adjustment, RESEQUENCING or TRADITIONAL SEROTYPING is advised.` |
| WARNING UNDIFFERENTIATED O-TYPE | `[ECTYPER_WARNING] Ambiguous Escherichia antigen pairs detected. Refer to DED-C-350C.`    |
| WARNING MIXED O-TYPE            | `[ECTYPER_WARNING] Mixed O type detected.`                                                |
| WARNING (WRONG SPECIES)         | `[ECTYPER_WARNING] Sample identified as <species>.`                                       |
| No serotype found               | `[ECTYPER_FAIL] No serotype found in ECTyper results.`                                    |
| No ECTyper data                 | `[FAIL] Re-run mikrokondo to generate ECTyper data.`                                      |

### Toxin and STX Validation

Detected virulence genes are filtered against a [validated Esherichia toxin list](https://github.com/phac-nml/typingQC/blob/main/assets/validated_toxins_250520.csv) and a [validated Escherichia STX subtype list](https://github.com/phac-nml/typingQC/blob/main/assets/validated_stxsubtypes_250520.csv).

| Field                   | Description                                               |
| ----------------------- | --------------------------------------------------------- |
| `Validated_Toxins`      | Comma-separated list of validated toxin genes (or `n/a`)  |
| `Validated_STXSubtypes` | Comma-separated list of validated STX subtypes (or `n/a`) |

Only toxin and STX genes present in the curated validation files are reported.

### ECTYPERQC Notes

- Serotype QC decisions are independent of toxin detection.
- Virulence genes are **reported only if validated**, not inferred.
- Final serotype validation and harmonization occur downstream in the `SEROTYPE` module.

## Module: EXCLUSIONS

### Purpose

Identifies **why a sample could not be typed** when typing QC cannot proceed.
This module provides a **clear failure reason** for unsupported species or missing mikrokondo output.

### Decision Matrix

Typing exclusions are assigned using the following decision rules:

| Condition                                          | typingQC_message                                                                                     |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| mikrokondo file **missing**                        | `[FAIL] No mikrokondo data file provided.`                                                           |
| Species **not** _Salmonella_ or _Escherichia_      | `[FAIL] TypingQC unsupported for species: <species>`                                                 |
| Supported species **with** mikrokondo file present | `[FAIL] Unknown reason – supported species with mikrokondo data present but sample failed TypingQC.` |

### EXCLUSIONS Notes

- Sequencing QC results are always reported whenever mikrokondo data is available, even for samples with untypable species.
- This module does **not** perform typing or sequencing QC - It exists to ensure **all samples receive a clear, reportable outcome**.
- Samples handled here require **manual review or upstream remediation**.

## Module: SEROTYPE

### Purpose

Generates the **final validated serotype** for each sample by combining:

- TypingQC results (PASS / WARNING / FAIL)
- Predicted serotype from mikrokondo
- Optional manual approval of WARNING results

This module produces the **final TypingQC report** used for downstream reporting.

### Decision Matrix

Validated serotypes are assigned based on **TypingQC status** and **serotype availability**.

| TypingQC Status | Predicted Serotype | approve_verification | Validated_Serotype    |
| --------------- | ------------------ | -------------------- | --------------------- |
| **FAIL**        | Any                | Any                  | `pending`             |
| **WARNING**     | Present            | No                   | `verification needed` |
| **WARNING**     | Present            | Yes                  | Predicted serotype    |
| **WARNING**     | Missing            | Any                  | `verification needed` |
| **PASS**        | Present            | Any                  | Predicted serotype    |
| **PASS**        | Missing            | Any                  | _(blank)_             |
| Other / Unknown | Any                | Any                  | `unknown`             |

### Effect of the `--approve_verification` Parameter

The `--approve_verification` flag controls how **WARNING-level TypingQC results** are handled during final serotype validation. WARNING-level results indicate minor issues that may still allow the predicted serotype to be reliable and suitable for submission to PulseNet Canada, but under normal circumstances require **manual verification** before reporting.

> This flag enables **batch approval** of WARNING-level results.

| Flag State | Behavior                                                            | Explanation                                                                                                                                                                       |
| ---------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Not set    | WARNING samples require manual verification                         | The pipeline marks these samples as `"verification needed"` in the final report. Users must review the predicted serotype and decide whether it is acceptable.                    |
| Set        | WARNING samples are treated as PASS and assigned predicted serotype | The pipeline automatically approves the predicted serotype, bypassing manual review. Useful for batch processing when users trust the predicted serotypes despite minor warnings. |

**Important:** This flag does **not** re-run typing or QC. It only affects how the SEROTYPE module interprets existing TypingQC results. The final serotype reported in the pipeline is **authoritative** and will reflect this approval decision.
